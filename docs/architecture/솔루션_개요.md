## 1. 기술 스택

| 레이어 | 기술 |
|--------|------|
| **게임 서버** | C++20 (MSVC), IOCP/RIO, ECS(SoA), FlatBuffers |
| **웹 마이크로서비스** | C# .NET 8, ASP.NET Core Minimal API |
| **API 게이트웨이** | YARP (Yet Another Reverse Proxy) |
| **매칭 서버** | Go 1.21 (인프라 준비 완료, 구현 예정) |
| **DB** | MySQL 8.x (MySqlConnector) |
| **캐시 / 메시지** | Redis (StackExchange.Redis) |
| **이벤트 스트림** | Kafka (Scheduler → 분석) |
| **스케줄링** | Quartz.NET |
| **패킷 직렬화** | FlatBuffers (C++ ↔ 클라이언트), JSON (관리 도구) |
| **인증** | JWT Bearer (Access 15분 + Refresh 30일), Cookie (AdminTool) |
| **알림** | Slack Webhook (Scheduler, AntiCheat) |

## 4. C++ 서버

### 4.1 게임 서버 (Game Server)

**위치:** `servers/game/`  
**포트:** 7700 TCP (IOCP/RIO) + UDP (동적 포트)  
**아키텍처 문서:** `servers/game/ARCHITECTURE_README.md`

#### 주요 역할
- ECS(Entity Component System) 기반 게임 월드 시뮬레이션
- 전투, AI, 물리, 스킬, 버프 등 100개 이상의 게임 시스템 운용
- 멀티스레드 Actor 모델: MPSC 큐 기반 비동기 메시지 처리

#### 핵심 시스템

| 시스템 파일 | 역할 |
|-------------|------|
| `actor_system.cpp` | Actor 생명주기 관리 (스폰·틱·소멸) |
| `actor_scheduler.cpp` | CPU 코어 기반 TickGroup 배분 |
| `skill_system.cpp` | 스킬 쿨다운·MP 검증·대상 해석 |
| `skill_effect_executor.cpp` | AbilityType 230종 효과 실행 (12개 카테고리) |
| `combat_system.cpp` | 데미지 계산·스탯 스케일링·상태이상 |
| `buff_system.cpp` | 버프·디버프·지속 효과 관리 |
| `ai_controller.cpp` | NPC AI (Recast/Detour 경로탐색, 행동트리) |
| `quest_manager.cpp` | 퀘스트 진행·완료·보상 |
| `inventory.cpp` | 아이템 슬롯·장착·스택 관리 |
| `guild_system.cpp` | 길드 운영 (게임 서버 측) |
| `season_system.cpp` | 시즌 콘텐츠·랭킹 |
| `terrain_grid.cpp` | 공간 인덱싱 (충돌·AoE) |
| `game_server.cpp` | 서버 메인 루프·IOCP/RIO 초기화 |
| `game_session.cpp` | 클라이언트 세션 상태머신 |

#### 네트워크 패킷 구조
```
[packet_id: uint16 LE][packet_size: uint32 LE][key: uint8] + FlatBuffers payload
```
- FlatBuffers 스키마: `scripts/flatbuffer/*.fbs` → `servers/common/flatbuffer/*_generated.h`
- 컴파일: `scripts/flatbuffer/compile.bat`

#### 설정 파일
```json
// config/dev/game_server.json
{
  "actor_thread_count": 4,
  "listen_ip": "127.0.0.1",
  "listen_port": 7700,
  "log_server_host": "127.0.0.1",
  "log_server_port": 9000
}
```

## 5. C# 게이트웨이 & 핵심 서비스

### 5.1 Gateway (:5000)

**위치:** `servers/gateway/`  
**역할:** 클라이언트의 유일한 HTTP 진입점. YARP 리버스 프록시로 백엔드 서비스에 라우팅.

#### YARP 라우팅 테이블

| 경로 패턴 | 대상 서비스 | 인증 필요 |
|-----------|------------|---------|
| `/v1/auth/**` | Login (:5001†) | ❌ |
| `/v1/world/**` | World (:5003†) | ✅ JWT |
| `/v1/channel/**` | World (:5003†) | ✅ JWT |
| `/v1/ranking/**` | Ranking (:5004†) | ❌ |
| `/v1/auction/**` | Auction (:5005†) | ✅ JWT |
| `/ws` | Chat (:5007†) | ✅ JWT |
| `/v1/mail/**` | Mail (:5008†) | ✅ JWT |
| `/v1/events/**` | Scheduler (:5009†) | ❌ |

† 내부 클러스터 주소 (docker-compose/k8s에서 서비스 이름으로 재정의)

#### 핵심 미들웨어
- `JwtValidationMiddleware` — Bearer 토큰 검증
- `RequestLoggingMiddleware` — 요청/응답 로깅
- Rate Limit: IP 당 200 req / 60초
- Maintenance Mode: 설정 토글로 전체 점검 모드 전환

### 5.2 Login (:6000)

**위치:** `servers/login/`  
**DB:** `account_db`

#### 인증 방식

| 엔드포인트 | 설명 |
|-----------|------|
| `POST /v1/auth/self/register` | 이메일/비밀번호 회원가입 (BCrypt 12) |
| `POST /v1/auth/self/login` | 이메일/비밀번호 로그인 |
| `POST /v1/auth/google/login` | Google ID Token 검증 |
| `POST /v1/auth/apple/login` | Apple Sign-In (JWKS 캐시 12h) |
| `POST /v1/auth/guest/login` | 게스트 (Device ID 기반) |
| `POST /v1/auth/token/refresh` | Refresh Token 교체 (1회용, 30일 TTL) |
| `POST /v1/auth/token/revoke` | 로그아웃 (토큰 폐기) |
| `POST /v1/auth/2fa/verify` | TOTP 2FA 검증 |

**보안:**
- Access Token: 15분 만료
- Refresh Token: Redis 저장, 30일 TTL, 1회용 로테이션
- 사용자 열거 방지: 없는 계정·틀린 비밀번호 모두 401 반환

### 5.3 Queue Server

**위치:** `servers/queue/`  
**상세 문서:** `servers/QUEUE_WORLD_README.md`

#### 역할
게임 서버 입장을 위한 실시간 대기열 관리.

#### 핵심 흐름
1. 클라이언트가 `/queue/enter` 요청 → Redis ZSET에 `{uid, timestamp}` 삽입
2. `QueueProcessorService` (500ms 루프)가 앞자리부터 처리
3. `WorldServer`에서 최적 게임 서버 + 채널 조회 (`DirectServerResolver` / `RemoteServerResolver`)
4. SSE (`/queue/status`) 로 실시간 순위·상태 푸시
5. 입장 티켓 발급 → 클라이언트가 게임 서버에 TCP 연결

**설정값 (appsettings.json):**

| 키 | 기본값 | 설명 |
|----|--------|------|
| `Queue:TicketTtlMinutes` | 30 | 입장 티켓 유효 시간 |
| `Queue:ReadyTtlSeconds` | 60 | 대기열 Ready 상태 TTL |
| `Queue:ProcessorIntervalMs` | 500 | 처리 루프 간격 |
| `Queue:ServerResolver:Type` | `remote` | `direct`(테스트) / `remote`(프로덕션) |

### 5.4 World Server (:6200)

**위치:** `servers/world/`  
**상세 문서:** `servers/QUEUE_WORLD_README.md`

#### 역할
게임 서버 레지스트리 + 채널 동적 스케일링.

#### 핵심 서비스

| 서비스 | 역할 |
|--------|------|
| `ServerRegistryService` | 게임 서버 등록·하트비트·제거 |
| `RouterService` | 최적 서버 선택 (라우팅 정책) |
| `ChannelService` | 채널 CRUD + 인원수 관리 |
| `HeartbeatMonitorService` | 30초 타임아웃으로 죽은 서버 제거 |
| `ChannelScalerService` | 30초마다 채널 증설(80% 초과) / 축소(20% 미만) |

**라우팅 정책 (appsettings.json `World:RoutingPolicy`):**

| 정책 | 설명 |
|------|------|
| `least-loaded` | 최소 접속자 서버 (기본값) |
| `map-affinity` | 동일 맵 기존 서버 우선 |
| `round-robin` | 순환 배분 |

**채널 스케일 설정:**

| 키 | 기본값 |
|----|--------|
| `Channel:MaxPlayersPerChannel` | 100 |
| `Channel:ScaleUpThresholdPercent` | 80 |
| `Channel:ScaleDownThresholdPercent` | 20 |
| `Channel:MaxChannelsPerMap` | 10 |

### 콘텐츠 & 경제

#### Ranking (:5000/5001)
**DB:** Redis only (MySQL 없음)

- Redis Sorted Set으로 O(log N) 삽입·조회
- Top-N 캐시: 3초 TTL
- 엔드포인트: Top 조회 / 개인 순위 / 점수 제출 / 삭제

#### Auction (:5004)
**DB:** `auction_db`

- 아이템 등록·입찰·낙찰
- `AuctionExpiryService` (HostedService): 1분마다 만료 경매 자동 처리

#### Season (:5018)
**DB:** `season_db` + Redis  
- 시즌 정의, 리워드 지급, 시즌 종료 시 랭킹 리셋

#### Event (:5011)
**DB:** `event_db` + Redis  
- 이벤트 생성·활성화·비활성화 (관리자 전용)
- 가챠 확률 공개 엔드포인트 (`GET /v1/info/gacha-rates`)

#### Housing (:5023)
**DB:** `housing_db` + Redis  
- 플레이어별 집 데이터 (데코레이션 그리드)
- 방문자 관리

#### Raid Lobby (:5022)
**DB:** Redis only  
- 5초 루프로 레이드 그룹 매칭
- `RaidTemplates[]`: 레이드 ID·난이도·인원·타임아웃 설정

#### Guild War (:5021)
**DB:** `guildwar_db` + Redis  
- 길드전 선포·공격·방어·항복 API
- Redis pub/sub으로 길드원에게 실시간 알림

#### Recommendation (:5024)
**DB:** Redis only  
- 플레이어 프로파일 기반 아이템·던전 추천
- `ProfileCacheService`: Redis 프로파일 캐시

#### Chat (동적 포트)
**DB:** Redis only

- WebSocket 엔드포인트 (`/ws`)
- `ChatBroadcastService` (HostedService): Redis pub/sub 메시지 수신 → WebSocket 브로드캐스트
- `MaxHistoryPerChannel`: 100, `MaxMessageLength`: 500

#### Mail (동적 포트)
**DB:** `mail_db`

- 우편 목록·읽기·첨부물 수령·삭제
- `POST /v1/internal/mail/send`: 다른 서버에서 호출하는 내부 API
- `MailCleanupService` (HostedService): 1시간마다 만료 우편 삭제
- `Mail:DailyPlayerSendLimit`: 50 (일일 발송 상한)

#### Notification (:5013)
**DB:** `notification_db` + Redis

- 알림함: 페이지네이션 조회 / 읽음 처리
- `POST /v1/internal/notifications/send`: 내부 발송 API
- `NotificationCleanupService` (HostedService): 만료 알림 삭제
- `Notification:KeepDays`: 30

#### Social (:5016)
**DB:** `social_db` + Redis

- 친구 목록·추가·수락·거절
- `PresenceService` (Singleton): Redis 기반 온라인 상태 관리

#### GM (:5012)
**DB:** `account_db` + Redis  
**RBAC:** `gm`, `gm_leader`, `super_admin` 역할 필요

|-----------|------|
| `POST /v1/gm/players/ban` | 계정 정지 |

| `POST /v1/gm/servers/maintenance` | 점검 모드 전환 |

#### Anti-Cheat (:5015)
**DB:** `anticheat_db` + Redis + Slack

- 클라이언트 의심 행동 신고 수신
- 서버 측 행동 유효성 검증
- 고신뢰도 탐지 시 Slack 알림
- 설정: `Alerting:WebhookUrl`, `Alerting:CriticalChannel`

#### Report (:5019)
**DB:** `report_db` + Redis

- 플레이어 신고 접수 (어뷰징·버그·핵)
- 신고 목록 GM 도구로 연동

#### Analytics (:5017)
**DB:** `analytics_db` + Redis

- 이벤트 수집 (로그인·퀘스트 완료·상점 구매)
- `AnalyticsFlushService` (HostedService): 배치 flush to DB
- `DailyStatsService` (HostedService): 일일 DAU·경제 통계 집계

#### CrossServer (:5020)
**DB:** `account_db`  
- 서버 인스턴스 간 데이터 동기화 (크로스 서버 이벤트, 공유 상태)

#### Patch Server (:5014)
**DB:** `patch_db` + Redis

- 클라이언트 버전 확인 (`GET /v1/patch/version`)
- 파일 매니페스트 제공 (CDN redirect)
- 버전 캐시: 600초, 파일 목록 캐시: 3600초

## 11. 서버 간 통신 맵

```
클라이언트
  │
  ├── TCP/UDP ──▶ Game Server
  │                  ├── Redis ──▶ Ranking
  │                  ├── HTTP ──▶ Community Server
  │                  └── (이벤트) ──▶ CrossServer
  │
  └── HTTP ──▶ Gateway (:5000)
                  ├── /v1/auth      ──▶ Login
                  ├── /v1/world     ──▶ World ──▶ Game Server (레지스트리)
                  │                         └── Queue
                  ├── /v1/ranking   ──▶ Ranking
                  ├── /v1/auction   ──▶ Auction
                  ├── /ws           ──▶ Chat
                  ├── /v1/mail      ──▶ Mail
                  └── /v1/events    ──▶ Scheduler

내부 서비스 간 호출:
  Scheduler ──▶ Mail (리텐션 메일 발송)
  Scheduler ──▶ Kafka (분석 이벤트)
  GM ──────▶ Mail (아이템 지급)
  GM ──────▶ Billing (재화 조정)
  Anti-Cheat ──▶ Slack (치트 알림)
  Scheduler ──▶ Slack (이상 감지 알림)
```
